心智 架构 Loop Context SKILL 事件 示例页 坑

1. 心智模型

Harness 强制

Loop、schema 校验、maxSteps / abort、Context 裁剪——代码说了算，不是靠 Prompt 自觉。

内核无协议泄漏

kernel/* 只认统一类型；OpenAI 的 tool_calls / role:"tool" 只活在 Adapter。

全量 vs 视图

内存 messages 全量保留；assembleContext 只裁发给模型的视图；结果再 append 回全量。

流式再执行

碎片边到边看；工具 arguments 拼完并 parse 后才 tool_start。

3. Agent Loop 交互

  1. run_start 组装初始 Context + tools
  2. skill_* 可选：目录 / 全文注入 / 挂 load_skill
  3. assembleContext 全量 → 出站视图
  4. llm_request 带 before/after + openaiRequest
  5. stream_detail / text_delta 碎片；工具拼完才执行
  6. assistant_message 完整消息（arguments 已是对象）
  7. 若有 toolCalls： tool_start → validate → execute → tool_end → append tool 消息 → 回到第 3 步
  8. 否则 run_end（finalAnswer + stopReason）

stopReason

completed max_steps timeout aborted tool_error error

4. Context：全量轨迹 vs 出站视图

内存 messages[]  ──完整历史──► Trace / append
        │
        │  assembleContext(identity | recent_n | char_budget)
        │  + repairToolOrphans
        ▼
   发给模型的 messages'
        ▼
   Adapter → openaiRequest（页面 JSON 可对照）
  • identity：原样发出
  • recent_n：system + 最近 N 条
  • char_budget：按字符粗估裁到预算

Trace 里 beforeCount 大、afterCount 小 = 只裁了视图，内存没删。

5. SKILL 四种加载

skillAuto 谁决定加载全文 怎么进 Context
off 勾选或 /skill:name 二次写入 system
match Harness 词重叠打分 二次写入 system
model 分类请求 JSON 二次写入 system
agent 模型调 load_skill tool 回写 纯 Markdown

对齐 Pi：目录常驻 + 读 SKILL.md。本项目用 load_skill 同构，成功结果不是 JSON 壳。

示例规程： skills/weather-brief.md、 skills/add-checklist.md

6. 事件速查

type 方向 备注
llm_request out 含 context 审计 + openaiRequest
stream_detail in 落盘；text_delta 仅推 UI
tool_start/end local 校验 + 执行 + 回写
skill_inject local catalog / auto / full

8. 常见坑

  1. 以为 Context 裁剪会删内存历史——不会，只影响出站。
  2. 半截 tool JSON 就执行——本项目禁止。
  3. load_skill 若再包 JSON 壳会误导——已改为纯 Markdown。
  4. Cursor 沙箱带代理起 Server → 出站可能 fetch failed；本机起或清掉代理。
  5. 密钥绝不能进前端 / Trace。
